三条量到的操作限界，下次照着做：

- **内存**：这台一共 1.9G，我（CLI）自己占 ~600M。副本 `level.dat` 解出来 89.6MB，直接起会被内核 OOM 杀掉
  （三次实测：`anon-rss:832092kB` / `994644kB` 时被杀）。加 `MALLOC_ARENA_MAX=1` 能过加载，
  但**每次起只够几分钟的量**，所以正确姿势是"起一次 → 一枪把所有要看的都抓完 → 立刻停"。
- **别用 `pkill -f "start-server .../sd0524.zip"`**：那个模式会匹配到我自己那条 bash 包装，把执行中的
  命令一起杀掉（实测 exit 143）。按 pid 杀，或者先 `pgrep` 再 `kill`。
- **`game.ticks_to_run = 1`** 一进来就把世界冻住：不冻结的话它一边跑一边吃内存，而且我读到的是"正在流动的
  带子"而不是他设计时的样子。

  `LuaTransportLine doesn't contain key contents`；数一格里有什么要用

## 他的基本排法：机器**竖着一列**，带子在列间**南北走**

这是和我现有几何根本不同的一点。我现在的 `stacked` 是"机器横着一排，进料带沿机器的一面东西走"；
他的是"机器竖着一列，带子在机器列之间南北走，臂开在机器的左右两面"。

实测切片（`nauvis @(-191,124)`，processing-unit / logistics / construction 三列并排；
`Mxxx/听false` = 组装机 + 它的 `circuit_set_recipe`，`|` = 管道，`Bv`/`B^` = 向南/向北的带）：

```
 125|B> B> B> B> B> Bv · · · · · · · · · · · · · · · ·
 126|o  Mproce/听false ▣ ▣ · Bv · · · · Mlogis/听false ▣ ▣ · · · · Mconst/听false ▣ ▣ ·
 127||  ▣ ▣ ▣ i> Bv Bv · · Bv i> ▣ ▣ ▣ i> Bv Bv i> ▣ ▣ ▣ i>
 128||  ▣ ▣ ▣ i< Bv Bv · · Bv ·   ▣ ▣ ▣ ·  Bv Bv ·  ▣ ▣ ▣ ·
 129||  Mproce/听false ▣ ▣ ^ Bv Bv · · Bv · Mlogis... ▣ ▣ · Bv Bv · Mconst... ▣ ▣ ·
 130||  ▣ ▣ ▣ i> Bv Bv · · Bv i> ▣ ▣ ▣ i> Bv Bv i> ▣ ▣ ▣ i>
      （x 从 -191 起：-191 是管，-190..-188 是机器，-187 是臂，-186/-185 是两条竖带）
```

读出来的律：

1. **一列机器 = 3 格宽 × 南北相连**；机器左右两面各站一只臂（`i>`/`i<`），臂外面是那一对竖带。
2. **一对竖带 = 两条带子 = 四个半股**，所以他一台机器**可达 4 种料** —— 这正是我 4 种料（141 条配方里的
   3/4 料那一档）现在做不到的原因：我只给一个面叠 2 条，他给两面各 2 条。
3. **股道实测确认了"一根带子两股各一种料"**：`带 -191,125 股1[electronic-circuitx4 || advanced-circuitx4]`
   —— 同一条带子两股两种料；而成品那一列 `带 -185,128 股1[processing-unitx3 || 空]` 只占一股。
   这与我 `dev/lane_side_probe.js` 的实测一致，是独立第二次确认。
4. **水/酸那一路：管子走在机器的另一面**（`|` 在 -191，紧贴机器西面），且用 `o`（地架带）与泵跨开。
   也就是说他"又吃又喝"的机器是**一面进料带、另一面进管** —— 我的 `fluid-back` 只会空北面那一行，
   所以他的这一档我完全没有。
5. 上层还有两条 `B<` 长带（`@ (6,25)` 那片的第 25/26 行）—— 那是他的**总路线双程**（一去一回两行），
   每列机器从总线上拐下来。

## 他手上的电路 = 我 0.80.0 铺的那一圈（值得单独学）

40 只组合器里有 6 组这样的排布（例：`nauvis @(-428,-126)` 与 `@(-99,279)`）：

```
常数组合器 (constant-combinator)  →  选择组合器 $ {operation=select, select_max=true, index_constant=0}
                                    →  选择组合器 $ {…, index_constant=0/1/2}  ×2~3，各自站在一台机器旁边
算术组合器 +  {operation=*,  second_constant=-1}   ← 取负
算术组合器 +  {operation=+,  second_constant=0}    ← 原样过一遍
```

三件要问的事，都在我下一步的能力范围内但先确认更省事：这组在做什么（`select_max=true` 配 `index_constant`
是"从最多的那个里挑第 i 个"）；那对 `*-1` / `+0` 是在算差值还是在做符号翻转；常数盒发的什么信号（我没读到
`filters` 的内容 —— 2.0 里常数组合器脚本读不到，可能得从别的口）。

**结论先放这里**：他的实践和我 0.80.0 的选择器一圈是同一个形状，这一条不用再问，可以放心继续做
通用产线那一格。

## 第二轮（实验室 / 原油 / 朝向 / API）

### 我先前一条"实测"是错的，得更正
`fluid-back` 上写的"组装机建起来一律朝北，所以这一档不许转"—— 那是**脚本 `create_entity` 的限界**，不是引擎的。
他档里读到的真机器（`p6.lua`）：

```
assembling-machine-2 朝向v 配方refined-concrete 需要[water]        机器左上(-218,126) 3x3
assembling-machine-2 朝向> 配方processing-unit  需要[sulfuric-acid] 机器左上(-194,126) 3x3
```

朝向是 `v`(南) / `>`(东) —— **玩家建/蓝图粘的机器真的带朝向**。所以"竖排 + 水管走侧面"这一档成立，
我的 `turnable=false` 应该改成"蓝图那一路可以转，只有模自己铺到地上的虚影不转"（那一路本来就还有连线的问题，
见 0.80.0）。

### 他的"很多种料"= 主线 + 两行地架带交替（实验室那片的实测）

```
 -36 | 臂(向南) 行                            ← 喂上排实验室
 -35 | 黄地架< 绿地架< 绿地架< 黄地架< …      ← 出口朝西的一行地架带，黄/绿交替
 -34 | 快带> ×24                              ← 他的主线
 -33 | 黄地架> 绿地架> 绿地架> 黄地架> …      ← 出口朝东的一行，与 -35 配成一对
 -32 | 臂(向北) 行                            ← 喂下排实验室
```

读法：**每种料走自己那一对地架带**，从主线**下面穿过去**，两侧各出一格喂给那一列的臂；黄/绿两档交替着排，
于是"一条主线能分出多少种料"不受"一个面只能叠两条带"限制 —— 这是 5、6 种料那条墙的真正解法，
比我打算自己发明的"两面进料"省地面也好落地得多。两排实验室再共用中间那一束（-40 那行臂 `-36`/`-32` 交替朝南/北）。

### 两条 2.0 API 名字定了（先前我试错了三回）
- 臂的筛选：**`arm:get_filter()`** 存在（`e.filter` / `inserter_filter` / `filter_mode` 全无）→ 能读"这只臂只管这种料"。
- 地架带类型：**`ug.belt_to_ground_type`** 在**件**上读得到（`input`/`output`），原型上没有这个键
  → 能精确数"哪两格配成一对"。（本模早先记的"只读、写不了"仍然成立，是另一件事。）
- 机器的液体口：**读不到** —— `get_fluidbox(idx)`、`e.fluidboxes` 都不存在。所以口只能靠实践约定
  （"他把机器转到口都在同一面"）+ 邻格有没有连着水的管子来反推，或者沿用本模 `boxes.lua` 那种"一格一格试"的慢见证。

### 待他确认的取整律（他口述的那条）
`≤0.5 条 → 占一股；>0.5 条 → 占一整条（两股）；再多以整条为单位往上`。
按这条：0.4→1 股、0.6→2 股、1.2→4 股、2.6→6 股。与我现在"向上贴半条（0.6→1 条，1.2→1.5 条）"**不同**，
差的那一格就是"半股给不给别人用"。

## 第三轮（原油区 / 六组组合器 / 液体 API / 插件）

### 地架带那一束的真实形状（实验室 y=-35/-34/-33 逐格读出来的）

```
-35 | fast:出< | under:入< | under:出< | fast:入< | fast:出< | under:入< | under:出< | fast:入< …
-34 | fast-transport-belt > ×24        ← 他的主线，一条
-33 | fast:入> | under:出> | under:入> | fast:出> | fast:入> | under:出> | under:入> | fast:出> …
```

上排一律朝西、下排一律朝东，黄(fast)/绿(underground)两档交替 —— **上下两两配成对，从主线下面穿过去**。
一条主线的位置因此带得起 4 种料（两档 × 两个方向）。他给的原因：同一种地架带不能在同一直线上交替。
（待他说清：同一列上下那两只是"同一种料的进与出"，还是"上下各是一种料"。）

### 液体 API：我先前"读不到"的那件事，有一半能读

- `entity.fluidbox`（属性）与 `entity:get_fluid_contents()` **存在** → 管子里、储液罐里是什么流体读得到；
  `get_fluidbox(i)` / `fluid_boxes` 那几种写法不存在（试了 7 种）。
- 所以"这台机器真实口在哪一格"仍然只能靠见证法（一格一格灌），但**"这根管子现在通的是什么流体"能直接读**
  —— 做形状时够用：铺完拿它验"管网红没红"。

### 原油那片（`advanced-oil-processing`，nauvis 约 (-19,187)）

5×5 炼油厂**朝东**建；管子走它的**东面**（`|` 一列 + `o` 穿地管），东边两台 `light-oil-processing`
朝西对着头接；储液罐 6 只在北边排成一行，泵在西边；**竖着走的料带**（`Bv`/`B^`）在更西边一条通道里并行。
也就是他一贯的分工：**液体走一面、固体走另一面，成品用罐子先囤一手**。

### 那六组组合器：旁边一台机器都没有

以 `(-320,-729)`、`(-428,-127)`、`(-505,-553)`、`(-64,-37)`、`(-99,279)`、`(152,-573)` 为中心 13×9 范围里
**没有任何生产建筑**。设置是：1 只常数组（filters 脚本读不到）+ 1~2 只选择器
（`select` / `select_max=true` / `index_constant=0`）+ 一对算术盒（`first_signal=signal-each`、
`×-1` 与 `+0` —— 这是"把整条网络的信号取负再原样发出去"的老写法）。判定它是不是废的只需一句：
你要留着还是我下次顺手把连线读干净？

### 插件这件事：这台档里读不到"已插的插件"

两轮扫（`assembling_machine_modules` 等 7 个库存常量都在，helmod 两页的 `summary_global.modules` 也空）
结论是他这档**还没插插件、也没有插件塔**（`beacon = 0`）。所以"产能随插件变"这件事我只能靠 helmod
那份数（0.74.0 起在读，0.79.0 的「把模块装上」就是它），**没有实测样本可学**。
