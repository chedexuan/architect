### B1 已闭：页上的模块现在进账

  写进答案、步进日志与窗口那一行；`modules_laid` 恒 0，因为**虚影身上装不了模块**（实测：
  `ghost.get_inventory(defines.inventory.crafter_modules)` 是 nil，2.0 没有 `set_module_info`；
  真机器可以 —— `real.insert({name="speed-module",count=1})` 回 0 未放入）。
- 现在看得见的地方：答案 `modules` / `modules_count` / `modules_said` / `modules_laid` / `modules_note`；
  每条线 `lanes[].modules` + `modules_said`；`rate_source.modules`（这份流量是装着哪几样算的）；
  选页那一列 `helmod_factories` 页与线两格都是 `modules`（件数）+ `module_said`（话）；
  窗口两条新行 `n-hm-modules` / `n-hm-modules-page`；整计划那按逐页挂。
- 还欠的一步（不是 bug，是功能）：把模块**装进地上已建好的真机器**那一扇门没做（真机器可以插，实测）。

### B2 已闭：换了机器，分子会改口了
- 一条规则：`flows.machine`（那份件数是按哪台机器折的）≠ 这一发真铺的那台 ⟹ 分子退回自算那一路，
  并交出 `reason = "machine_swapped"` 与 `helmod_aside = {helmod_machine, laid_machine, crafts_per_min,
  modules}`。窗口那一行 `n-hm-rate-self` 把两个数都念出来（helmod 那份原数、按地上这台算的那份）。
- 为什么不能留着 helmod 那份：每分工艺术数由地上这台的**速度**决定，而它对地上那台的**模块**一无所知。
  拿 X 的数铺 Y 的线正是"放得下但不生产"那一类错，而这个数绑的是"这条线要几条带子"。
- 反过来也钉住了：只有地上就是 helmod 点名的那台，才允许说 `source = "helmod"`。
- 实测踩到的就是这一条：`steel-furnace` 不开放时压线换成石炉，`crafts_per_min` 仍写钢炉那份 375/分，
  而按石炉是 187.5/分 —— 这一版之后它会退回并说明。
- 门禁：`helmod_ghosts_e2e` 3b4 三条 + 窗口一行；那一节的活压线需要钢炉，按 `layout_ledger` 的老规矩
  借配方、用完照原样还（实测还掉了：`steel-furnace enabled=false`）。


### B3 已闭：`dev/quick.sh` 里那些没门禁的面现在会自己说

## 1b. 新发现的 bug（⑤ 那条门禁抓到的）

### B4 已闭：进料侧的带子运力漏了 `(1 + belt_stack_size_bonus)`
- 0.72.0 把这一项折进 `lane_of` 时改了两处调用，漏了第三处 `belt_carry`（control.lua 里"这条带子一分钟
  过几件"那一句）—— 于是 `feed_plan.per_lane` / `lanes_wanted` / `machines_per_line`（一条线能喂几台）
  一直按**没加成**的运力说话，而同一张卡的成品侧 `lane_carry` 说的是折过的。表现就是玩家报的那句
  "helmod 说一条够，你为什么要两条"，只是藏在进料那一半。
- 抓到它的是 ⑤ 新加的那条"借一级加成再跑同一张取整表"的门禁：加成 1 级时成品侧分母翻倍、进料侧不动。
- 修法是给那一处补上 `force`；门禁跑完照原样还 force 那一格（`belt_head_e2e` / `belt_stack_probe` /
  `arm_side_probe` / `belt_rate_e2e` / `helmod_ghosts_e2e` / `fluid_line_e2e` 全绿）。

## 2. #35「全部用 helmod 的数据」那一刀的剩余

- **② 已落地**（0.73.0）：压线链的分子只从 `card_example` 里那一个出口 `rate_for(machines)` 出来，
  带 `flows` 时读的是 helmod `get_recipe` 折过的 `count`。
- **③ 已落地**（0.76.0）：`belt_need(count_per_min, belt, force)` 定义在 `lane_of` 旁边（只有这一处会算
  "要几条带子"），`belts = ceil(need*2)/2` 向上贴半条；答案里 `belt_need_helmod` 与 `lane_plan` /
  `belt_choice` 两个口径并列，窗口一行 `n-hm-belt-need`。取整表钉在 `dev/layout_ledger.js`
  （0.4/0.6/0.8/1.1/1.6 → 0.5/1/1/1.5/2，分母读答案自己的 `per_min`，所以加成是几级都跑同一张表）。
- **④ 已落地**（0.77.0）：`form-belt-tip` 与 `hint-helmod` 都改口径 —— 数取自 helmod 那棵树（折过
  productivity/模块/信标/quality），**用哪一档带子是我们这一格定的**（helmod 的默认档位在读不到的
  `storage.preferences` 里），容量里折的加成读的是 `force.belt_stack_size_bonus`，不是它的覆盖值。
  压线每条线交 `belt_chosen_by = "caller"|"adequate"`，窗口那一行据此走两条不同的话术。
- **⑤ 已落地**（0.78.0）：`layout_ledger` 钉取整表（分母读答案自己的 `per_min`）、`lanes = belts × 2`、
  档位同一档、`bonus` 等于当场读到的 `force.belt_stack_size_bonus`，并**把加成借高一级再跑同一张表、跑完
  照原样还**；`helmod_ghosts_e2e` 钉 `belt_need_helmod` 与取整方向、点名/自动两种说法各一条。
  那条"借一级再还"的门禁当场抓到一处真 bug（见 §1 B4）。
- 小账：`count_deep`（深算那份台数）还没交出去；选页那一列（`M.helmod_factories`）不带流量，
  选的时候看不出哪条线大；每一行一次 `get_recipe` 远程调用（一页几十行时是几十次深拷贝）。
